- Config layers merge by top-level key, not per leaf -- a leaf merge needs a real YAML parser in the session-title hook's hot path; top-level blocks are what the flat awk reader can split safely (#7).
- The global ~/.claude/issue-tracker.yaml is a base layer only, never a standalone fallback -- a global repo target would point unconfigured repos at the wrong tracker (#7).
- Env overrides are limited to backend, github.repo, jira.site and jira.project -- those are what retargeting a run needs; everything else stays in files (#7).
- Hook and collectors resolve the config once per process -- a per-get resolve costs ~0.7s on Git Bash and SessionStart is synchronous (#7).
- /new-tab opens the tab without an offer step -- the operator invoking it is the consent; the offer-only rule covers tabs a flow would open on its own initiative.
- Babysit treats an empty reviewDecision as review-clear only when the PR is green on its head (mergeStateStatus CLEAN, a collector-visible workflow run a success on headRefOid, no changes-requested review), never while CI runs or when there is none -- no human approved it, and without required reviews there is usually no auto-merge either, so the merge row's direct-merge fallback would land before the checks finish (#154).
- The babysit merge-readiness fields (headRefOid, mergeStateStatus, reviews) are read by the command, not added to session-brief-collect.sh -- a field the token cannot read would fail the collector's one gh pr view call and blind every row and /session-brief with it, as statusCheckRollup did (#154).
- Babysit updates a BEHIND PR by merging the base in (gh pr update-branch), never by rebasing -- a rebase of a pushed branch needs the force-push the safety rails forbid (#158).
- Babysit updates a BEHIND PR only when its reviewDecision is empty -- updating an approved PR can dismiss the approval, and updating one that waits on a reviewer reruns CI for nothing each time the base moves (#158).
- /resume-initiative's status-drift check never infers a Jira child's state from its status name; without the status category the child is unknown and yields no finding -- workflow names are per-project, and a wrong guess would report drift on a consistent epic (#150).
- A legacy mirror's checked line matches a child in the merged status (jira.merged_transition), not only a Done one -- /work-issue --finish checks the line at merge, before a release closes the ticket (#150).
- The contract's status field stays the tracker's own name; closed-ness for the drift check is read by the command from the backend payload -- changing the return shape of four contract operations for one legacy-only check is not worth it (#150).
- A "no" from git merge-base --is-ancestor is trusted only in a full clone; in a shallow clone, or when the commit is missing locally, the git host is asked, no answer means unknown, and the clone is never deepened for the operator -- a released commit behind the graft exits 1 like an unreleased one, and unshallowing rewrites their repo and can be a large fetch (#149).
- ait_commit_in_tag asks the host about the tag's locally resolved commit sha in the caller's owner/repo, not the tag name in gh's default repo -- a branch sharing the tag's name, or an upstream remote, could answer "contained" for an unreleased commit and close its ticket (#149).
- Tracker nudges are user-only (systemMessage), never Stop-hook feedback to the model -- a false positive must cost a glance, not a turn; a model-facing opt-in is a followup (#114).
- The deferral nudge needs a multi-word deferral phrase AND a commit or PR in the session AND nothing filed -- design talk defers constantly and is not ready to file; bare "follow-up" / "TODO" are too common to mean anything (#114).
- Jira resume context comes from a local breadcrumb the commands write, not from Jira REST in the hook -- hooks cannot reach the MCP, and a REST token is a credential path the plugin avoids (#114).
- A nudge marker is created before the message is printed, and a failed create means silence -- a repeated nudge gets tuned out, which is the main way the feature fails (#114).
